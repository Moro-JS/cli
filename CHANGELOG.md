# Changelog

## v1.4.0

### Changed

- **`dev` restarts the server itself** — hot reload no longer needs nodemon. `moro dev` runs `npm run build && node <entry>` and runs it again when a `.ts`, `.js` or `.json` file under the watched paths changes (`src` by default, `--watch` replaces it) or when you enter `rs`. A project that has nodemon installed keeps running under nodemon, with its own nodemon configuration.
- **`dev` loads TypeScript configuration and routes on Node.js 20** — on a Node.js that cannot load TypeScript itself (before 22.18) the compiled entry runs through the project's `tsx`, as the generated `start` script does; before, the app started without `moro.config.ts` and its routes there. A TypeScript project without `tsx` gets one line saying so. On Node.js 22.18 and newer the command is unchanged.
- **A commented `trustProxy` line in generated configuration** — `moro init` and `moro config init` write it in the `server` block, ready to uncomment for an app behind a load balancer or reverse proxy. No value is set. `config init` leaves it out when the installed framework has no such setting.
- **Fewer packages are installed with the CLI** — `nodemon`, `glob` and `zod` are no longer dependencies (the CLI loaded none of them itself), `chokidar` moves to 4.x and `figlet` to `^1.11.3`.
- **Newer minimum versions in generated projects** — `moro init` writes `zod ^4.6.6`, `joi ^18.3.1`, `ws ^8.21.0`, `better-auth ^1.7.7`, `mysql2 ^3.23.1` and `drizzle-orm ^0.45.2`.
- **Generated authentication runs on Better Auth** — `moro init --features=auth` writes `src/middleware/auth.ts` on the framework's Better Auth adapter (`createAuthMiddleware()`): email and password sign-up and sign-in, sessions, the session token as a Bearer token, GitHub and Google sign-in once their client id and secret are in `.env`, and `/api/profile` and `/api/admin` behind `requireAuth()` and `requireAdmin()`. With `--database=sqlite`, `postgresql` or `mysql` users and sessions are stored in that database and the tables are created at start-up; with the other choices they start in Better Auth's in-memory store, and the file and the README say what to pass instead. The generated project no longer depends on `bcryptjs` or `jsonwebtoken`, and `.env` gains `BASE_URL` and the four OAuth variables in place of `JWT_EXPIRES_IN` and `BCRYPT_ROUNDS`, which nothing read.
- **`middleware add auth` writes the same sign-in** — `auth()` with email and password through `betterAuth`, OAuth providers from the environment and an in-memory store to start on. `--config` takes `secret`, `expiresIn`, `basePath`, `baseURL`, `trustedOrigins`, `debug` and `useSecureCookies`.
- **The request timeout is written as `server.timeouts.request`** — `moro init` writes it that way in `moro.config.ts`. `moro config init` writes it for a project on `@morojs/moro` 1.8.0 or newer and keeps `server.timeout` for a project on an older framework; it reads the installed version, then the range in `package.json`, and uses the new form when neither says.
- **WebSocket message compression is off in generated projects** — `--websocket=socket.io` and `auto-detect` write `compression: false` in `src/index.ts`, with a comment on what `true` does (smaller messages for clients that support it, more CPU per message).
- **`drizzle-kit` is a development dependency in generated projects** — `--database=drizzle` writes it to `devDependencies`; the running app only loads `drizzle-orm`.

### Upgrade notes

- In a project without nodemon, `moro dev` used to build and start the app once and end with it. It now keeps watching: after the app exits it waits for the next change, and Ctrl+C ends it with exit code 130. `--port` and `--host` are passed to the app only when given, so their defaults no longer override the `PORT` / `HOST` of the project's `.env`.
- Existing generated projects are unaffected until their dependencies are updated.
- Projects generated by earlier CLI versions that still have `websocket.compression: true` will start compressing WebSocket messages after upgrading the framework, and can set it to `false` to keep today's CPU profile.
- The authentication file `moro init` used to generate passed `auth()` a `credentials` provider, `callbacks` and `session.strategy`, which the framework's Better Auth adapter does not use and names in start-up warnings; its own `/api/auth/login`, `/api/auth/logout` and `/api/auth/status` routes and the `admin@example.com` development login did the work. Newly generated projects have none of these: accounts are created with `POST /api/auth/sign-up/email`, and the routes are Better Auth's (`/api/auth/sign-in/email`, `/api/auth/sign-out`, `/api/auth/get-session`). Projects generated earlier keep their file.
- `middleware add auth` no longer applies `strategy` and `trustHost` from `--config`: Better Auth has no equivalent, and the command says what to use instead. The generated file imports `better-auth`, so the project has to have it installed.

## v1.3.8

### Added

- **`moro stack` commands** — scaffold and inspect pre-wired application stacks (`api`, `saas`, `edge`) composed from `@morojs/stacks`:
  - `moro stack list` — list the available stacks
  - `moro stack describe <name>` — show what a stack composes, its options, and peer dependencies
  - `moro stack new <project-name>` — scaffold a new project from a stack (`--stack`, `--database`, `--package-manager`, `--force`)
  - `moro stack eject <name>` — eject a stack's composition into your project (`--force`)
- **`moro new --stack <api|saas|edge>`** — scaffold directly from a curated stack during project creation.

  > The stack commands require the optional `@morojs/stacks` package; if it isn't installed, they exit with an install hint.

### Changed

- **Node.js 20 is now the minimum supported version** — the CLI's `engines` field is bumped from `>=18` to `>=20`, matching `@morojs/moro` v1.8+. Node 18 has reached end-of-life.
- **Generated projects now target Node 20** — `moro new` scaffolds a `package.json` (`engines.node: ">=20.0.0"`), `Dockerfile` (`FROM node:20-alpine`), and Serverless/Lambda config (`runtime: nodejs20.x`) on Node 20.

### Upgrade notes

- No breaking command or API changes. New projects require Node 20+; existing generated projects are unaffected until regenerated.
